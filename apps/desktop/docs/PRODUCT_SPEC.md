# Monument Product Spec — Alpha

## One-line product definition

A product-first macOS development environment where OpenAI Codex is the engineering brain, work is organized as durable tasks, and the live artifact is the primary workspace.

## Who it is for

Primary alpha user:
- builds web products with Codex frequently;
- wants agent autonomy without losing visibility or control;
- switches between visual iteration, code, terminal, Git, and verification;
- cares about finish quality, not just generating code that compiles.

Secondary users later:
- product engineers;
- designers who can work with code through visual context;
- small teams running multiple parallel Codex tasks.

## Core product objects

### Project
A trusted local repository plus runtime metadata. Holds known dev commands, preview URLs, active worktrees, VibeOS configuration, and project-level display metadata.

### Task
The central unit of work. A task owns or references:
- Codex thread id;
- Git branch;
- optional worktree;
- user goal / acceptance contract;
- runtime preview/process group;
- current aggregate diff;
- evidence ledger;
- task status.

Task statuses:
`draft → ready → working → review → blocked → ready_to_ship → done`.

### Run
A user instruction and the resulting Codex turn. Multiple runs can happen inside one task.

### Artifact
What the user is actually building or inspecting. For alpha this is a web preview; later it can be simulator output, API behavior, CLI output, component gallery, etc.

### Evidence
Proof generated by deterministic checks or explicit review: tests, build, screenshot, browser state, console/network status, accessibility result, diff review, migration proof.

## Default workspace

```text
┌ Project / Task navigation ┬ Primary Artifact ┬ Codex Task Context ┐
│                           │                  │                    │
│ Tasks                     │ Live Preview     │ Plan               │
│ Files                     │ or Code          │ Activity           │
│ Projects                  │                  │ Review findings    │
│                           │                  │ Composer           │
└───────────────────────────┴──────────────────┴────────────────────┘
                    Contextual runtime drawer
        Terminal · Problems · Console · Network · Git · Evidence
```

## Alpha must-have behavior

1. Open local repository.
2. Detect or choose running dev server.
3. Show real web preview.
4. Connect to one managed Codex app-server process.
5. List Codex threads scoped to the project.
6. Resume and fork threads.
7. Stream a turn with understandable product-level activity.
8. Render approval requests as explicit blocking cards.
9. Show changed files and aggregate diff.
10. Switch Preview ↔ Code without losing task context.
11. Inspect a rendered element and attach visual/DOM/source context to the next turn.
12. Show VibeOS route and evidence state.
13. Open terminal/log/network surfaces only when needed.
14. Persist window/project/task UI state locally.
15. Recover safely after app restart without duplicating running work.

## Explicit non-goals for first alpha

- replacing every VS Code extension;
- implementing our own model gateway;
- cloud collaboration;
- mobile platforms;
- a marketplace;
- supporting other coding agents;
- bundling a private copy of OpenAI UI assets or tokens.

## Success criteria

A strong alpha should make this workflow materially easier than a generic IDE:

> Open repo → choose task → tell Codex what to change → watch real product → inspect problem visually → send exact context → review changes/evidence → ship.

The user should be able to complete a normal visual product change without manually opening a separate browser, terminal, Git client, or Codex chat window.
